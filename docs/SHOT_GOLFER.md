# Bounded golfer scenery initialization

`shot_golfer.c` converts the complete original `20a58d` initializer through its
return at `20a5a9`. It installs the real next callback `20a5aa`. That subsequent
drawing stage is not implemented here. This is a real child initializer, not an
interactive swing or a completed golfer animation.

## Converted work

- Reset the second layer's scroll bytes and enqueue the actual course palette
  group, background color and background stamp.
- Preserve the original special tee/terrain 6 branches, task scratch and signed
  animation-kind distinction. The ordinary path samples actual terrain 24
  pixels ahead, or 28 pixels for terrains 11–14, and preserves the genuine
  three-attempt advancement and scratch fields.
- Run the original short-distance angle/green choice using the existing exact
  angle helper. Queue the selected static ground art, or initialize its actual
  animation countdown. Preserve the original per-terrain foreground stamp and
  frame counts.
- Register tag 51 in object slot 5 with its real metadata, project the pin using
  the independently verified perspective helper, and select its exact sprite
  animation from the original unsigned distance thresholds.
- Preserve saturated object, palette and stamp queue behavior. Both native
  object-tag views remain synchronized even when registration is dropped.

The initializer plans and validates its work before mutating caller-owned
outputs. It does not sample host input, invoke another child, or advance the
scheduler, object renderer, drawing head or palette consumer.

## Resource and state contract

Use `ntm_shot_golfer_initialize` with the actual scene context, borrowed terrain
resources, existing terrain-detail word, player-status byte and original-derived
resource spans. The state owns task scratch, terrain-sampling intermediates,
projection direction and the second perspective scratch word. The first
perspective scratch word remains in the existing display scratch state.

`reference/shot_golfer_case_common.py` resolves the private inputs. Terrain maps
are bounded by their actual row tables and RLE runs, not padded cartridge
windows. The exporter/application must bind the current large map and close
map. Existing first-open terrain resources have null map spans and are not
sufficient for this child.

Tag 51 uses nine genuine selectors 88 through 120 in steps 4 with ordinary
velocity/4 indexing. Tag 27 keeps its independent dense mapping. Global animation
capacity remains 40, so existing asset-family structures do not grow.

`reference/report_shot_golfer_resources.py` reports sizes without exposing data:

- All 54 large/close map pairs total 1,288,529 raw bytes across 108 distinct sources.
  Per-hole loading avoids making every map resident. First-hole pairs are 6,514,
  6,266 and 5,790 bytes across the three courses. The largest pair is 44,244 bytes.
- New scenery stamps need 18 descriptors totaling 4,380 bytes and one 14,464-byte
  tile-table prefix: 18,844 incremental raw bytes over current opening assets.
- Tag 51 adds 432 raw bytes beyond the new tag 27 sprite spans when shared prefixes
  and existing animations are reused.

These figures exclude structures, alignment and code. They are not a claim that
all new data fits the current stock target or DD image. No control frontend,
exported target or preserved baseline is regenerated by these source checks.

## Verification

Run `tools/check-shot-golfer.sh` after activating the local m68k toolchain.
It runs 2,430 authored initializer/resource/queue cases on the host, with
ASan/UBSan, and on static m68020/QEMU. Both ordinary and private asset-copy
backends are checked against the unchanged original core:

- 648 initializer comparisons cover all 15 supported terrain classes, three
 courses, short-distance selection, real 54 map pairs, projection, palette,
 stamp and object saturation, task scratch and queued resource identities.
- 219 genuine drawing-head drains verify the produced scenery art without
 advancing a frame or fabricating a consumer.
- 405 real tag 51 registration/tail/head rounds cover every selected animation,
 animated/frozen state, flips and clipped/wrapped coordinates.

Comparisons include all nonstack game RAM and hardware/video bytes. Only measured
original stack writes are excluded. No original instruction or resource is
patched and no cartridge bytes, extracted art, captures or private input hashes
are embedded in source.
